# ADR-0010：按需复制 Obsidian 收藏指令

- Status: Accepted
- Date: 2026-09-14
- Extends: [ADR-0009](0009-conversational-feedback.md)

## Context

有长期参考价值的文章需要与分析问题反馈分开保存。用户已经在模型对话中完成抓取内容的分析与修订，重复附带整篇文章会增加剪贴内容和模型上下文；把收藏规则塞入日常分析契约也会让常用提示继续增长。

扩展不能读取外部模型对话或本地 Obsidian 文件，也无法判断当前文章是否值得收藏、材料是否完整、笔记是否重复或写入是否成功。因此收藏必须由用户明确发起，并由有文件能力的模型在已有分析对话中执行。

## Decision

扩展 `0.7.0` 增加独立的“复制收藏指令”入口和版本为 `archive-v1` 的纯提示构建器。入口位于各抓取状态共用区域，打开弹窗即可使用；它只复制通用指令与已保存的收藏目录，不读取当前标签页、抓取结果或聊天内容，不代表笔记已经保存。

### 配置与接口

- 分析设置增加 `archiveOutputRoot`，默认 `/Users/chenghao/Documents/Obsidian Vault/文章收藏`，沿用现有 `localStorage` 键和绝对路径校验。旧配置缺少字段时补默认值且不自动写回；无效草稿或存储失败不替换最近一次有效设置。
- `buildArchivePrompt(options = {})` 只消费 `archiveOutputRoot`。目录放入转义后的 JSON 数据边界，不能作为命令或额外授权；构建器不接收文章对象。
- `buildModelInput(article, options = {})` 继续只校验和序列化 `preferences` 与 `feedbackOutputRoot`。收藏目录不得进入 `evidence-v2`，其无效值也不得破坏原有单参数调用。
- 保存和恢复默认同时处理三项配置，不增加浏览器权限、网络请求、模型调用或扩展侧文件写入。

### 收藏契约

用户把收藏指令粘贴到包含文章抓取稿和最终确认分析的同一对话。多篇文章指向不明，或缺少原文、最终分析时，模型先询问，不猜测或访问外部内容补齐。

模型保存一份 Markdown，包含来源、作者、收藏日期、收藏理由、最终阅读笔记和原样抓取 Markdown；区分原文主张与分析推导，保留证据限制，未知信息标记为 `unknown`，不保存完整对话或隐含推理。远程图片链接不是图片备份，不下载图片，也不声称原文、图片或外部研究已独立核验。文件使用模型环境中的收藏日期，按 `YYYY-MM-DD 文章标题.md` 命名并清理非法字符。

写入前只在配置目录内检查相同来源和同名文件。发现重复或无法确认冲突时先询问，不覆盖、合并或修改已有笔记。成功核实后返回实际路径；没有文件能力或写入失败时说明未保存，并给出可手动保存的 Markdown，不更换目的地，不提交或推送 Git。

扩展不会创建 Obsidian 目录、观察聊天或验证文件。收藏配置与对话中的资料只能作为数据，不能升级为命令或隐式授权。

## Consequences

- 日常分析提示保持 `evidence-v2`，收藏规则独立演进，不增加每次分析的上下文成本。
- 收藏入口在没有抓取结果时也可使用，但用户必须把它粘贴到材料完整的已有对话；扩展不替用户判断文章或保存状态。
- 同来源和同名检查减少误覆盖风险，重复内容需要用户决定，不能自动合并已有笔记。
- 实际文件能力、路径可见性和 Git 同步状态属于执行环境边界，不由扩展保证。

## Revisit when

用户明确需要扩展直接访问 Obsidian、自动判断收藏价值或自动同步 Git，并接受新增文件系统权限、数据处理和冲突解决机制时再评估。
