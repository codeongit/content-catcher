# ADR-0011：证据定位索引与按主张类型评价的分析契约

- Status: Accepted
- Date: 2026-09-18
- Extends: [ADR-0004](0004-redacted-diagnostics-and-synthetic-fixtures.md)、[ADR-0007](0007-advisory-analysis-readiness.md)
- Partially supersedes: [ADR-0008](0008-evidence-grounded-model-handoff.md)、[ADR-0009](0009-conversational-feedback.md) 的模型交接版本、证据定位及支撑评价细节；其他产品与反馈边界保留。
- Partially superseded by: [ADR-0012](0012-decision-oriented-plain-language-analysis.md)（2026-09-18）：分析契约升级为 `evidence-v4`，增加通俗表达默认与偏好按维度覆盖，细化决策导向、独立验证核对和非强制评级。证据索引、抓取上下文、原文保留及反馈边界继续有效。以下保留原决策正文。

## Context

同一份抓取稿的分析可能因主张选取不同而出现不同评级。模型可能把作者较强的预测收窄为较容易成立的机制命题，或者用局部工程建议替代文章的主要决策；这时仅比较“强”或“中”不能判断哪个分析更准确。另一种偏差是对概念分类、机制说明、效果比较和趋势预测统一要求实验，混淆内部论证完整性与外部事实核验。

现有交接虽要求依据和推导区分，但读者回查长文中的具体依据仍依赖人工搜索。抓取上下文只给总清理量，也容易被误读为正文缺失率。需要提供可回查的位置和足以解释清理过程的统计，同时保留原文与本地隐私边界。

## Decision

扩展 `0.8.0` 使用 `evidence-v3`。只扩展离线模型输入与脱敏诊断，不接入模型 API、网络服务、自动评分或付费评测。

### 分析契约

- 先复原作者主旨、原始主张与论证，再评价对应主张；不得悄悄收窄或替换命题后把较强评级归给原主张。
- 区分原文主张、原文依据与显式标记的推导。实用见解优先服务文章的主要决策，并保留适用条件、行动、机制、依据与风险边界。
- 内部支撑按主张类型判断。概念分类看边界与解释，机制说明看条件与因果链，效果比较与预测需要相应验证；没有实验不自动使所有主张降级。
- 外链、引用材料和未转写图片仍未核验。内部论证成立不等于外部真实性已确认，索引也不提高原文证据本身的强度。
- 五段式继续作为默认组织方式，保留篇幅、重点与形式偏好，不强制表格；偏好不能成为事实依据。

### 证据索引与原文

`evidence-index.js` 导出同步纯函数 `buildEvidenceIndex(markdown)`，由 `analysis-prompt.js` 调用，返回 `{ id, type, startLine, endLine, excerpt }` 数组。函数不访问 DOM、文件、时间、网络或模型。

- 块编号从 `B0001` 起按正文顺序递增，只用于这份 Markdown 的局部定位。
- 行号从 1 开始，以包含 frontmatter 的完整 Markdown 为准。闭合的首部 frontmatter 不建立索引，但保留其行号占用；不能因跳过元数据重新从正文第一行计数。
- 代码围栏按完整块处理，内部 Markdown 符号不另起索引块。索引只提供轻量定位，不声称支持全部 Markdown 语法或恢复原网页结构。
- 摘录对块文本仅做首尾 `trim`，再取前 48 个 Unicode 码点；不归一化内部空白，不把代理对截断。模型应回查整块及上下文，不能仅凭摘录作结论。
- 索引作为 `<evidence_index>` JSON 区放在 `<captured_content>` 之前，JSON 尖括号转义。索引摘录与正文均为不可信资料，不能覆盖分析契约或用户授权。
- 原始抓取 Markdown 不插入编号、不改写、不分块重复输出；模型输入只追加一份原样抓取稿。普通复制、下载与收藏原文仍使用原始文章对象。

JSON 数据边界有助于避免数据直接闭合标签，但不是提示注入防护的完整保证。插件不能强制外部模型遵守规则。

### 抓取上下文与清理统计

抓取上下文增加 `extensionVersion`、`capturedAt` 和 `cleanupStages`，保留图片未转写、外链未核验及既有就绪信息。扩展版本取自 `article.diagnostic.extensionVersion`，抓取时间取自 `article.capturedAt`，缺失时为 `unknown`。

诊断 schema 升级为 v3，在 `content.cleanup.stages` 中依序记录 `structure`、`placeholder-images`、`noise`、`site-tail` 四个清理阶段。模型上下文只投影白名单阶段的 `{ rule, removedElementCount, removedTextLength }`，不复制额外诊断字段，不记录被删除的原文。

清理比例描述选中内容在解析清理前后的文本量变化，不等于正文缺失率，也不能直接证明关键段落被删除。原有 ADR-0007 提示阈值及建议性、非阻断行为不变。

### 兼容与验证

- `buildModelInput(article, options = {})` 保留单参数调用，选项仍为分析偏好和反馈目录。
- `archive-v1`、权限、无模型 API、本地设置、按需反馈保存、不覆盖与失败降级规则保持不变；没有自动学习或聊天回传。
- 离线回归验证索引位置、frontmatter 和代码边界、Unicode 摘录、JSON 转义、原文唯一且原样保留、阶段统计及字段降级，不以提示文本存在证明模型效果。
- 手工语义观察仅按需使用合成文章或不入库材料，关注主张收窄、主旨偏移、概念分类被按实验标准统一降级等偏差。记录模型、提示版本与观察限制，不把单次差异当作普遍改善，不要求默认付费调用。
- 真实浏览器加载、剪贴板、下载与布局仍由人工维护者验收；未收到实际结果时标记待人工验证。

## Consequences

- 读者能按编号和原文行号回查依据，维护者也能区分抓取缺失、引用错误和分析命题改变。
- 索引及上下文增加输入长度，但不再重复拼接分块全文；短摘录不能替代阅读原始材料。
- 分阶段统计帮助解释清理过程，仍不能单独判定正文完整性，也不能恢复被删除内容。
- 契约更明确，但不承诺所有模型都会遵循、不同模型输出一致或分析质量已被实证提升。

## Revisit when

用户明确需要跨版本稳定引用、完整 Markdown 语法解析、原网页对照、模型会话集成或规模化评测，并接受相应复杂度、数据边界和调用成本时再评估。
