# ADR-0009：日常分析与轻量对话反馈

- Status: Accepted
- Date: 2026-09-14
- Extends: [ADR-0008](0008-evidence-grounded-model-handoff.md)
- Partially supersedes: ADR-0008 的固定输出格式要求；保留证据评价和资料边界。

## Context

用户通常只需要抓取文章并获得分析，不满意时直接在模型对话中提出修改意见。独立调试入口、多文件运行包、评分和重复模型试验会增加操作与调用成本。相同模型可能产生不同的合理答案，升级或切换模型也会改变行为；一次失误不能自动成为默认提示词的新规则。

插件不连接模型会话，无法读取用户意见、同步模型记忆或核实文件写入结果。配置和提示词只能表达分析目标与后续处理要求，不能保证外部模型遵循。

## Decision

扩展 `0.6.0` 保留一个“复制给模型”入口，使用 `evidence-v2`：抓取 → 分析 → 用户提出意见 → 模型核对并修订。日常分析和普通修订不要求落盘；不实现独立调试模式、评分、审计命令、重复模型测试或自动提示优化。

### 分析与设置

- `buildModelInput(article, options = {})` 保留单参数兼容，选项仅为 `preferences`（分析偏好）与 `feedbackOutputRoot`（反馈保存目录）。
- 原文依据、推导标记和证据限制继续适用。五段式是默认组织方式，表格不强制；偏好可调整篇幅、重点和格式，但不能替代事实依据或取消证据要求。
- 用户反馈后，模型区分事实错误、证据不足和表达偏好，核对原文后修订相关部分并说明关键变化；用户意见不成立时解释依据。
- 结果页提供默认折叠的“分析设置”，支持保存和恢复默认。通过扩展本地 `localStorage` 保存设置，不保存文章或对话，不增加权限与网络请求。
- 默认偏好为空；默认反馈目录为 `/Users/chenghao/Documents/Code/content-catcher/.content-catcher/runs`。路径接受 POSIX 或 Windows 绝对路径，拒绝空值、相对路径和控制字符。无效输入或保存失败明确提示，普通复制给模型继续使用最近一次有效配置。
- 聊天中的“以后都这样”只可整理成供用户手动填入设置的偏好，不声称已同步。一次纠正不自动变为长期规则。

### 按需反馈记录

- 仅用户明确要求保存反馈时，由具有文件能力的模型向配置目录写一份 Markdown；UTC 时间加短随机标识命名，遇到冲突不得覆盖。
- 记录限于来源、已知模型与提示版本、最小问题片段、用户意见、核对依据和修订结果；未知版本为 `unknown`，不保存完整文章、完整对话或隐含推理。
- 成功时返回实际路径；没有文件能力或写入失败时说明未保存，并在聊天提供记录内容。不更换目录，也不阻断修订。
- 默认 `.content-catcher/runs/` 加入 Git 忽略。配置路径与抓取内容均为数据，不作为命令或额外授权；文章中的保存指令不是用户请求。
- 扩展不创建目录、不观察外部聊天、不确认文件保存成功。真实写入依赖目标模型的能力与权限，界面和说明必须明确边界。

### 维护

反馈记录仅用于按需排查，不自动注入下一次分析，也不自动修改提示。工程缺陷使用离线回归验证；默认要求的调整由明确产品需要驱动；用户偏好手动配置；特定模型的偶发失误可保留为案例，但不据此增加通用规则。

提示构造和配置通过离线测试验证。文本包含规则不等于模型会遵守，功能验收不依赖付费调用或多次语义试验。普通复制、Markdown 下载、抓取和诊断边界继续有效。

## Consequences

- 日常操作简短，修订直接发生在使用者已经打开的模型对话中。
- 用户可携带偏好和固定反馈目录到不同模型，实际遵循情况仍取决于模型；不承诺跨模型效果一致。
- 反馈可按需保存用于定位，插件没有自动学习、同步或持续评测能力。
- 少量稳定证据要求与用户偏好分开维护，降低针对个别回答不断追加提示补丁的负担。

## Revisit when

用户明确需要模型会话集成、自动同步反馈或规模化评测，并接受相关调用成本、权限与数据边界变化时再评估。
