# ADR-0012：通俗表达与决策导向的分析契约

- Status: Accepted
- Date: 2026-09-18
- Extends: [ADR-0009](0009-conversational-feedback.md)
- Partially supersedes: [ADR-0011](0011-evidence-index-and-analysis-contract.md) 的分析提示版本、默认表达和证据评价细节；证据索引、抓取上下文、原文与反馈边界继续有效。

## Context

可回查的依据还不足以让分析容易理解和用于决策。术语密集、逐项评级、重复的限制或建议，会掩盖文章的主旨；把模型判断的一致性视为准确性或业务效果，也会高估证据。用户因此批准调整默认表达与分析重点。

这次变更属于明确的产品选择，不是把某篇真实文章或某次模型回答变成所有任务的专门规则。无需新增设置字段、模型 API 或自动评测系统。

## Decision

扩展 `0.8.1` 使用 `evidence-v4`，保持单一“复制给模型”流程。

### 表达默认与用户偏好

- 内置默认使用通俗中文、少术语、短段落；必要术语给出直白解释，保留适用范围、前提和例外，不以简化语言为由简化事实。
- `preferences` 只覆盖用户明确指定的表达维度，例如语言、术语程度、篇幅、重点或格式；未指定的维度继续使用内置默认。
- `preferences` 的存储默认值仍为空字符串，不把默认文风写入用户设置，不改存储键、配置字段或函数接口，也不迁移或覆盖已有偏好。
- 五段式继续作为默认组织方式，表格不强制；偏好不能替代事实依据、取消证据要求或赋予写文件权限。

### 从决策到证据

分析先说明文章帮助读者作出什么判断或决定，以及作者提供什么方法；材料没有明确决策时，说明它讨论的问题，不补造用途。随后复原作者完整主张、按块编号回查依据，解释证据实际支持到哪里。不得用更窄、更容易成立的命题替代原主张，也不能用“发现问题”的证据证明“方法已解决问题”。原文主张、原文依据与分析推导仍须区分，推导显式标记。

证据评价匹配主张类型。概念分类看定义和一致性，机制说明看条件与推理；效果、比较和预测看相应验证。不因没有实验统一否定概念分析，也不把报告数字、重复判断一致、判断准确和真实业务改善互相替代。

涉及独立验证、泛化或消除数据泄漏的主张时，核对验证数据是否参与了训练、规则选择或调参，以及最终检验是否独立。若正文未交代，只能说明尚未证明，不能猜测完整流程或断言一定存在泄漏。内部论证是否完整与外部事实是否核验分开判断。

不强制给出“强、中、弱”等等级；可以直接说明支持范围、缺口和理由。实用见解须指向具体且不同的决策，给出行动、作用机制、依据与风险边界，不用同一建议换措辞凑数。共通的抓取和证据限制集中说明，只对个别结论补充必要的特殊限制。

### 不变的边界

`buildModelInput(article, options = {})`、证据索引格式、抓取上下文字段、原样正文保留与 JSON 数据边界不变。普通复制、下载、`archive-v1`、分析设置与按需反馈保存沿用既有行为。

扩展不新增网络请求、模型 API、权限、评分、自动学习或聊天同步。仅按明确用户请求保存反馈；路径是数据而非授权，失败时不更换目录、不声称保存成功。

### 验证与状态

离线测试验证契约文本、设置兼容与输入数据边界，不能证明外部模型会遵守或分析效果已提高。真实浏览器验收继续由人工维护者负责。

维护手册提供四个合成语义观察案例及成功、失败标准，分别覆盖概念与效果区分，完整强主张、一致率与选规数据，不同决策的行动，以及保留条件的通俗表达。案例不含真实文章，也不需要默认付费调用。

本次用一份覆盖上述四类问题的合成材料，在当前会话中完成 `evidence-v3` 与 `evidence-v4` 各一次定性观察。两个版本均识别主要证据缺口，新版解释了更多术语、减少等级标签，但输出未明显缩短；单次结果不足以判断整体优劣。四个独立案例、偏好覆盖的实际模型表现和用户选用的外部模型仍为**待验证**。按需观察时记录模型、提示版本、偏好和具体偏差；没有执行结果就不记为通过，也不自动触发提示补丁。

## Consequences

- 默认输出更明确地服务于阅读理解与实际决策，用户仍可覆盖自己关心的表达维度。
- 已有空偏好、保存设置和收藏流程无需迁移，文章原文与定位方式保持兼容。
- 较少等级和重复限制不意味着降低证据要求；判断理由、适用条件与未知部分仍需清楚表达。
- 指令可离线检查，模型实际遵循情况仍待观察，不能把版本升级作为质量提升证明。

## Revisit when

用户明确需要新的分析模式、结构化输出接口或规模化模型评测，并接受相应维护成本、权限与数据边界时再评估。
