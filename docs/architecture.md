# 架构说明

## 数据流

```text
当前标签页 DOM
  → extractor.js 识别正文与元数据
  → 清洗 DOM、规范化图片和链接
  → Markdown 转换
  → 通用分析适用性提示
  → 本地分析设置（偏好、反馈目录、Obsidian 收藏目录）
  → analysis-prompt.js 建立定位索引并组装证据化模型输入（仅“复制给模型”）
  → archive-prompt.js 组装独立收藏指令（无需读取标签页或抓取结果）
  → popup.js 预览、复制或下载
```

扩展的所有处理都发生在用户浏览器中。目前不存在后端服务，也不会发送网络请求。用户手动把模型输入粘贴到外部模型后，分析、对话修订和按需文件写入发生在该模型的环境中，扩展不能观察这些结果。

## 分析适用性提示

正文解析完成后，`extractor.js` 只根据清理后字数、正文选择策略和清理前后文本量生成建议性提示。规则不读取图片数量、作者、标题格式、网站关键词或外部数据，也不会改变正文、阻止复制或阻止下载。`popup.js` 最多展示两个提示，并在用户主动点击“复制给模型”时把提示与证据化分析契约附加到 Markdown 前；普通复制和下载保持原始内容。

## 证据化模型交接

`analysis-prompt.js` 是无 DOM 依赖的纯模块。`buildModelInput(article, options = {})` 保留单参数调用兼容性，选项仍只提供 `preferences` 和 `feedbackOutputRoot`。它从文章对象投影抓取上下文，建立定位索引，再在原样正文前附加 `evidence-v4` 分析契约。五段式继续作为默认组织方式，表格不强制；正文、摘录与路径均作为数据，不能覆盖用户授权或充当命令。

表达默认写在分析契约中：使用通俗中文、少术语、短段落，必要术语给出直白解释，并保留关键条件。用户的 `preferences` 只覆盖其明确涉及的语言、术语、篇幅、重点或格式等维度，其他维度沿用默认值。存储默认值仍为空字符串，不把内置风格写入设置，不做配置迁移，也不改变存储键或函数接口。表达偏好不能替代证据或取消事实边界。

契约围绕文章讨论的决策及作者提供的方法展开；没有明确决策时说明讨论的问题，不强行补造用途。先复原作者主旨与完整主张，再说明证据类型、实际支持范围和判断理由，不强制评为“强、中、弱”。概念分类检查定义与一致性，机制说明检查条件与推理；效果、比较和预测需要相应验证。报告数字、模型判断的一致性、判断准确性和业务效果分开评价，也不能用发现问题的证据证明方法已解决问题。

作者声称独立验证、泛化或消除数据泄漏时，契约要求核对验证数据是否参与过训练、规则选择或调参。正文没有交代独立数据或划分范围时，说明结论尚未被证明，不反过来断言已发生泄漏。内部论证与外部真实性继续分开，不因未核验外链统一降低概念分析的评价。

实用见解应针对不同的具体决策给出行动、机制、依据和边界；推导必须标记，同一建议不换措辞凑数。共通限制集中说明，仅在具体结论需要时补充特殊限制。索引结构、原文保留与反馈保存边界不随表达变化。

### 证据定位索引

`evidence-index.js` 导出的 `buildEvidenceIndex(markdown)` 是同步纯函数，不读取 DOM、时间、文件、网络或模型。输出为 `{ id, type, startLine, endLine, excerpt }` 数组：

- `id` 从 `B0001` 开始依次编号，只在同一份 Markdown 内用于定位，不是跨版本内容标识。
- `startLine` 与 `endLine` 是包含 frontmatter 的完整 Markdown 中从 1 开始的行号；跳过已闭合的首部 frontmatter，但不扣减它占用的行数。
- 代码围栏内的内容按完整块处理，不把代码中的标题、列表或表格语法识别成正文块。
- `excerpt` 对块文本仅做首尾 `trim`，再取前 48 个 Unicode 码点；不合并内部空白，不把 UTF-16 代理对拆开。摘录用于回查，不替代所在块及其上下文。

模型输入在原样 `<captured_content>` 前放置 `<evidence_index>` JSON 区；JSON 中的尖括号转义，避免数据直接闭合外层标签。索引与摘录是不可信资料，不承诺解析全部 Markdown 语法，也不构成事实验证或提示注入防护的完整保证。输入只包含索引和一份原样抓取稿，不追加另一份分块全文；普通复制、下载及收藏保留的抓取稿不插入块编号。

### 抓取上下文

上下文新增 `extensionVersion`、`capturedAt` 和 `cleanupStages`。版本取自 `article.diagnostic.extensionVersion`，时间取自 `article.capturedAt`；缺失时为 `unknown`，不猜测来源。`cleanupStages` 从 `article.diagnostic.content.cleanup.stages` 投影，只保留 `{ rule, removedElementCount, removedTextLength }`。`rule` 白名单为 `structure`、`placeholder-images`、`noise`、`site-tail`；不携带被删除文本、额外诊断字段或整份 DOM。清理前后变化及比例只描述解析过程，不等于正文缺失率；现有 ADR-0007 提示阈值不变。

抓取上下文中的图片数只说明 Markdown 保留了多少图片引用，不参与 ADR-0007 的就绪判断。插件不会读取图片像素、打开外链或核验引用材料，因此这些能力恒定标记为未执行。普通复制与下载不经过该模块。

## 独立收藏交接

`archive-prompt.js` 同样是无 DOM 依赖的纯模块。`buildArchivePrompt(options = {})` 只读取 `archiveOutputRoot`，生成版本为 `archive-v2` 的通用收藏指令；它不接收文章对象，也不查询当前标签页或对话。收藏目录放在转义后的 JSON 数据边界中，不能充当命令或文件写入授权。

弹窗把“复制收藏指令”放在各抓取状态共用的区域，所以首次打开、抓取中、成功或失败时均可使用。复制行为只写入剪贴板，不创建目录、笔记或成功状态。用户需把指令粘贴到已有的文章分析对话，由外部模型根据当前对话判断材料是否齐全，并在写入前检查目标目录内的同来源或同名笔记；重复或冲突不明时先询问，不覆盖或修改已有内容。

收藏原文单独成节，直接插入原始 Markdown，不额外包裹整篇代码围栏或整体缩进。原文自带的代码块、元数据及空白保留；聊天交付的外层围栏不属于文件内容。格式要求由独立收藏契约传递，扩展不增加文件格式修复器，也不批量迁移既有笔记。

收藏失败时外部模型应说明未保存并返回可手动保存的 Markdown，不更换目标目录。扩展不读取对话、不访问 Obsidian 文件系统、不下载远程图片、不核验外链，也不执行 Git 提交或推送。`archive-v2` 与 `evidence-v4` 独立版本化，收藏配置不会进入日常分析输入。

## 本地设置与对话反馈

弹窗提供“复制给模型”和独立的“复制收藏指令”，以及页头下方默认折叠的“分析设置”。设置通过 `localStorage` 持久化空字符串默认偏好、反馈目录和 Obsidian 收藏目录，不保存文章、响应或聊天历史，也不需要新增 Chrome 权限。路径支持 POSIX 和 Windows 绝对路径，拒绝空值、相对路径和控制字符。旧配置缺少收藏目录时补默认值但不自动写回；无效输入或存储失败明确显示，最近一次有效配置继续用于复制。

模型收到用户意见后，按契约核对材料并修订相关内容；“以后都这样”只形成供用户手动写入设置的偏好建议。一次纠正不自动改变默认提示词，模型也无法通过本流程自动修改扩展设置。

仅用户明确要求保存反馈时，交接指令才要求具有文件能力的模型，在配置目录创建一份带 UTC 时间和短随机标识的 Markdown；不覆盖已有记录。默认目录为 `/Users/chenghao/Documents/Code/content-catcher/.content-catcher/runs`，仓库忽略该目录。文件包含来源、已知版本、最小问题片段、用户意见、核对依据和修订结果，未知版本为 `unknown`，不包含完整文章、完整对话或隐含推理。

文件写入由外部模型执行，配置路径不是插件的写入权限。成功时模型返回实际路径；能力不足或保存失败时返回未保存原因与可复制的记录内容，不改换目录、不阻断修订。没有回传通道或自动成功状态，反馈也不自动进入下一次模型输入。

## 诊断数据流

诊断 schema v3 只保存最终正文根节点的脱敏 DOM，并附带正文选择策略、候选节点结构评分、元数据字段来源、清理前后统计及分阶段计数。清理依序记录 `structure`、`placeholder-images`、`noise`、`site-tail`，不保存各阶段被删除的原文；模型上下文只取白名单阶段与安全计数字段。普通文本会替换为长度相同的安全占位内容；视觉标题和尾部推广只保留语义标记，原始文案不会进入诊断文件。链接、图片地址、图片替代文本和日期属性使用固定安全值。

诊断 HTML 可以重新进入解析器以复现依赖文本长度、视觉标题和尾部截断的行为。它不包含候选节点的完整外围 DOM、计算样式、脚本状态或元数据原值；候选选择问题主要依据随附评分摘要定位，再由维护者建立最小合成 fixture。

阶段计数针对实际抓取的清理过程；总量与阶段文本量统一使用 `textContent` 的空白正规化结果，避免页面节点与脱离页面的克隆因 `innerText` 布局语义不同而出现矛盾。诊断导出会预先剔除脚本、表单等结构并替换图片 URL，因此重放不保证结构清理和占位图片阶段的计数完全相同；噪声和尾部截断可根据保留的安全结构验证。标题转换在清理统计采样之后执行，不计入删除量。

## 模块职责

- `manifest.json`：最小权限声明，只申请当前标签页、脚本注入和下载权限。
- `popup.*`：用户界面、设置持久化和扩展生命周期管理。
- `analysis-settings.js`：默认设置、反馈与收藏目录校验和配置规范化。
- `evidence-index.js`：同步生成指向原始 Markdown 的证据定位索引，不修改原文。
- `analysis-prompt.js`：调用索引模块，把文章对象和已保存设置转换为带证据、对话反馈规则和安全抓取上下文的模型输入。
- `archive-prompt.js`：只根据已保存收藏目录生成独立、版本化的 Obsidian 收藏指令。
- `extractor.js`：站点适配、通用正文评分、DOM 清洗和 Markdown 转换。

站点差异集中在 `SITE_ADAPTERS`。适配器只定义匹配条件、正文根节点、站点元数据和额外清洗；通用评分与 Markdown 转换保持共享。

## 解析策略

1. 优先尝试明确的站点或语义选择器，例如微信的 `#js_content`、`article` 和 `main`。
2. 当没有明确正文节点时，对候选容器按文本量、段落数、标题数、图片数和链接密度评分。
3. 删除导航、表单、广告、分享、推荐和评论等常见噪声。
4. 将懒加载图片地址和相对链接转换为绝对地址。
5. 将清洗后的 DOM 转换为 Markdown。

微信公众号会直接使用 `#js_content`，并额外执行作者/公众号拆分、尾部推广截断和受限的 DOM 视觉标题识别。仅独立 `section` 中带明确章节语法或完整强调的短编号标题可提升；普通段落、列表、引用、表格和代码不提升。通用站点只尊重原生标题，不再扫描导出的 Markdown 猜测编号标题。诊断脱敏与解析共用标题分类，以安全语义标记支持重放。

代码块独立序列化文本、换行与行容器，保护语法高亮中的注释等内容，并在普通 Markdown 空白整理期间隔离代码载荷。围栏长度根据代码中的反引号确定；不根据外部 CSS 猜测行结构。

预览为只读，可选择内容复制。普通复制读取文章对象中当前视图的内容；模型交接与下载读取同一份原始 Markdown，预览控件不作为导出数据源。

## 扩展原则

- 新站点优先增加小型适配规则，不复制整个解析器。
- 通用启发式必须保留，避免扩展退化为站点白名单。
- 新增清洗规则时必须避免删除正文中的合法短内容。
- 将来接入 AI 时，通过独立 provider 接口实现，不把 API Key 写入扩展源码。

## 回归机制

- `tests/fixtures/` 存放人工构造、不包含真实文章版权内容的最小 HTML 样本。
- `tests/extractor.test.mjs` 在 jsdom 中执行与扩展完全相同的 `extractor.js`。
- GitHub Actions 在每次推送和 Pull Request 时运行通用页面、微信页面和诊断脱敏测试。
- 真实页面出现问题时，先通过扩展导出脱敏诊断样本，再将结构压缩成人工 fixture，最后补充失败测试和修复规则。
- 模型输入和设置采用离线测试，检查索引边界、完整 Markdown 行号、Unicode 摘录、JSON 数据边界、原文唯一且原样保留、安全清理统计、配置、反馈保存条件和降级行为；文本测试只证明交接指令与数据正确，不能证明外部模型遵守指令。
- 收藏提示采用独立离线测试，检查目录数据边界、材料缺失、重复冲突和写入失败规则；弹窗测试确认复制入口不依赖页面抓取。
- 反馈按需排查，不引入评分账本、付费模型重复测试或自动提示词优化；不同模型的偶发回答差异不自动转化为通用规则。
