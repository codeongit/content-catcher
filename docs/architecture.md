# 架构说明

## 数据流

```text
当前标签页 DOM
  → extractor.js 识别正文与元数据
  → 清洗 DOM、规范化图片和链接
  → Markdown 转换
  → 通用分析适用性提示
  → 本地分析设置（偏好、反馈目录、Obsidian 收藏目录）
  → analysis-prompt.js 组装证据化模型输入（仅“复制给模型”）
  → archive-prompt.js 组装独立收藏指令（无需读取标签页或抓取结果）
  → popup.js 预览、复制或下载
```

扩展的所有处理都发生在用户浏览器中。目前不存在后端服务，也不会发送网络请求。用户手动把模型输入粘贴到外部模型后，分析、对话修订和按需文件写入发生在该模型的环境中，扩展不能观察这些结果。

## 分析适用性提示

正文解析完成后，`extractor.js` 只根据清理后字数、正文选择策略和清理前后文本量生成建议性提示。规则不读取图片数量、作者、标题格式、网站关键词或外部数据，也不会改变正文、阻止复制或阻止下载。`popup.js` 最多展示两个提示，并在用户主动点击“复制给模型”时把提示与证据化分析契约附加到 Markdown 前；普通复制和下载保持原始内容。

## 证据化模型交接

`analysis-prompt.js` 是无 DOM 依赖的纯模块。`buildModelInput(article, options = {})` 保留单参数调用兼容性，选项只提供 `preferences` 和 `feedbackOutputRoot`。它把现有解析指标投影为独立的抓取上下文，并在正文前附加版本化分析契约。`evidence-v2` 保留证据与推导要求，将五段式改为默认组织方式，允许偏好调整篇幅、重点和格式，表格不强制。偏好不能成为事实依据或取消证据要求；正文与路径均作为数据，不能覆盖用户授权或充当命令。

抓取上下文中的图片数只说明 Markdown 保留了多少图片引用，不参与 ADR-0007 的就绪判断。插件不会读取图片像素、打开外链或核验引用材料，因此这些能力恒定标记为未执行。普通复制与下载不经过该模块。

## 独立收藏交接

`archive-prompt.js` 同样是无 DOM 依赖的纯模块。`buildArchivePrompt(options = {})` 只读取 `archiveOutputRoot`，生成版本为 `archive-v1` 的通用收藏指令；它不接收文章对象，也不查询当前标签页或对话。收藏目录放在转义后的 JSON 数据边界中，不能充当命令或文件写入授权。

弹窗把“复制收藏指令”放在各抓取状态共用的区域，所以首次打开、抓取中、成功或失败时均可使用。复制行为只写入剪贴板，不创建目录、笔记或成功状态。用户需把指令粘贴到已有的文章分析对话，由外部模型根据当前对话判断材料是否齐全，并在写入前检查目标目录内的同来源或同名笔记；重复或冲突不明时先询问，不覆盖或修改已有内容。

收藏失败时外部模型应说明未保存并返回可手动保存的 Markdown，不更换目标目录。扩展不读取对话、不访问 Obsidian 文件系统、不下载远程图片、不核验外链，也不执行 Git 提交或推送。`archive-v1` 与 `evidence-v2` 独立版本化，收藏配置不会进入日常分析输入。

## 本地设置与对话反馈

弹窗提供“复制给模型”和独立的“复制收藏指令”，以及页头下方默认折叠的“分析设置”。设置通过 `localStorage` 持久化空字符串默认偏好、反馈目录和 Obsidian 收藏目录，不保存文章、响应或聊天历史，也不需要新增 Chrome 权限。路径支持 POSIX 和 Windows 绝对路径，拒绝空值、相对路径和控制字符。旧配置缺少收藏目录时补默认值但不自动写回；无效输入或存储失败明确显示，最近一次有效配置继续用于复制。

模型收到用户意见后，按契约核对材料并修订相关内容；“以后都这样”只形成供用户手动写入设置的偏好建议。一次纠正不自动改变默认提示词，模型也无法通过本流程自动修改扩展设置。

仅用户明确要求保存反馈时，交接指令才要求具有文件能力的模型，在配置目录创建一份带 UTC 时间和短随机标识的 Markdown；不覆盖已有记录。默认目录为 `/Users/chenghao/Documents/Code/content-catcher/.content-catcher/runs`，仓库忽略该目录。文件包含来源、已知版本、最小问题片段、用户意见、核对依据和修订结果，未知版本为 `unknown`，不包含完整文章、完整对话或隐含推理。

文件写入由外部模型执行，配置路径不是插件的写入权限。成功时模型返回实际路径；能力不足或保存失败时返回未保存原因与可复制的记录内容，不改换目录、不阻断修订。没有回传通道或自动成功状态，反馈也不自动进入下一次模型输入。

## 诊断数据流

诊断 schema v2 只保存最终正文根节点的脱敏 DOM，并附带正文选择策略、候选节点结构评分、元数据字段来源和清理前后统计。普通文本会替换为长度相同的安全占位内容；视觉标题和尾部推广只保留语义标记，原始文案不会进入诊断文件。链接、图片地址、图片替代文本和日期属性使用固定安全值。

诊断 HTML 可以重新进入解析器以复现依赖文本长度、视觉标题和尾部截断的行为。它不包含候选节点的完整外围 DOM、计算样式、脚本状态或元数据原值；候选选择问题主要依据随附评分摘要定位，再由维护者建立最小合成 fixture。

## 模块职责

- `manifest.json`：最小权限声明，只申请当前标签页、脚本注入和下载权限。
- `popup.*`：用户界面、设置持久化和扩展生命周期管理。
- `analysis-settings.js`：默认设置、反馈与收藏目录校验和配置规范化。
- `analysis-prompt.js`：把文章对象和已保存设置转换为带证据、对话反馈规则和抓取上下文的模型输入。
- `archive-prompt.js`：只根据已保存收藏目录生成独立、版本化的 Obsidian 收藏指令。
- `extractor.js`：站点适配、通用正文评分、DOM 清洗和 Markdown 转换。

站点差异集中在 `SITE_ADAPTERS`。适配器只定义匹配条件、正文根节点、站点元数据和额外清洗；通用评分与 Markdown 转换保持共享。

## 解析策略

1. 优先尝试明确的站点或语义选择器，例如微信的 `#js_content`、`article` 和 `main`。
2. 当没有明确正文节点时，对候选容器按文本量、段落数、标题数、图片数和链接密度评分。
3. 删除导航、表单、广告、分享、推荐和评论等常见噪声。
4. 将懒加载图片地址和相对链接转换为绝对地址。
5. 将清洗后的 DOM 转换为 Markdown。

微信公众号会直接使用 `#js_content`，并额外执行作者/公众号拆分、尾部推广截断和视觉标题提升。站点规则只增强边界判断，正文转换仍复用通用流程。

## 扩展原则

- 新站点优先增加小型适配规则，不复制整个解析器。
- 通用启发式必须保留，避免扩展退化为站点白名单。
- 新增清洗规则时必须避免删除正文中的合法短内容。
- 将来接入 AI 时，通过独立 provider 接口实现，不把 API Key 写入扩展源码。

## 回归机制

- `tests/fixtures/` 存放人工构造、不包含真实文章版权内容的最小 HTML 样本。
- `tests/extractor.test.mjs` 在 jsdom 中执行与扩展完全相同的 `extractor.js`。
- GitHub Actions 在每次推送和 Pull Request 时运行通用页面、微信页面和诊断脱敏测试。
- 真实页面出现问题时，先通过扩展导出脱敏诊断样本，再将结构压缩成人工 fixture，最后补充失败测试和修复规则。
- 模型输入和设置采用离线测试，检查配置、证据规则、反馈保存条件和降级行为；文本测试只证明交接指令与数据正确，不能证明外部模型遵守指令。
- 收藏提示采用独立离线测试，检查目录数据边界、材料缺失、重复冲突和写入失败规则；弹窗测试确认复制入口不依赖页面抓取。
- 反馈按需排查，不引入评分账本、付费模型重复测试或自动提示词优化；不同模型的偶发回答差异不自动转化为通用规则。
