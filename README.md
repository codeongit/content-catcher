# Content Catcher

Content Catcher 是一个本地运行的 Chrome 扩展，用来识别当前网页的主要内容并导出 Markdown。

## 功能

- 通用新闻、博客和文章页面正文识别
- 微信公众号文章专项清洗
- 提取标题、作者、发布日期、站点和原始链接
- 规范化懒加载图片与相对链接
- Markdown 与纯文本只读预览，可选中文字复制；所有导出读取原始抓取结果
- 显示面向模型分析的轻量内容提示
- 复制带证据定位索引、抓取上下文和证据评价规则的模型分析输入
- 本地保存分析偏好和反馈目录，支持在模型对话中核对、修订分析
- 随时复制独立的 Obsidian 收藏指令，把已确认的文章分析按需交给有文件能力的模型保存
- 一键复制当前内容、复制给模型或下载 `.md`
- 不上传页面内容，不需要 API Key
- 可主动导出脱敏 DOM 诊断样本，用于复现站点结构问题

## 本地安装

1. 打开 `chrome://extensions/`。
2. 开启“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择本项目中的 `extension/` 目录。

## 开发

扩展本身没有运行时依赖，也不需要构建即可加载。回归测试需要 Node.js 22+。

```bash
npm install
npm test
make check
make package
```

- `make check`：检查 manifest、文件完整性和关键能力。
- `npm test`：离线验证解析、模型输入组装和弹窗配置行为。
- `make package`：在 `dist/` 中生成可分发 ZIP。

## 当前边界

- 只处理当前已经加载的页面，不绕过登录、付费墙或网站权限。
- 图片以远程 URL 保留在 Markdown 中，不下载图片文件。
- Chrome 内置页面和扩展商店等受保护页面不能抓取。
- 暂不包含批量抓取、历史库和内置 AI 分析；分析由用户自行选择的外部模型完成。

## 用于模型分析

预览用于检查抓取结果，不支持编辑正文。普通复制使用当前 Markdown 或纯文本视图，“复制给模型”和下载始终使用同一份原始抓取 Markdown。

扩展只对可能显著影响模型分析的情况给出建议确认提示：正文较短、只能回退到整个页面、清理阶段删除了大部分文字。提示不会阻止复制或下载，也不检查图片数量、作者缺失和轻微格式问题。

“复制给模型”会在 Markdown 前附加 `evidence-v4` 分析契约、抓取上下文和证据定位索引。内置表达默认是通俗中文、少术语、短段落；必要术语用直白的话解释，同时保留影响判断的条件。五段式仍是默认组织方式，表格不强制。

分析先说明文章帮助读者做什么决定、作者提供什么方法，再复原完整主张、核对依据能支持到哪里；没有明确决策时说明文章讨论的问题，不补造用途。不能把强主张换成更容易成立的局部机制，也不能把发现问题当作已经解决问题。重要结论可通过块编号和行号回查正文，并区分原文主张、原文依据与自身推导。不强制给“强、中、弱”等等级，更重要的是说明支持范围和理由。

概念分类与机制说明不能仅因没有实验统一降级。涉及效果、比较或预测时，应核对相应验证；例如判断多次是否一致，不等于判断准确或业务效果更好。声称已独立验证时，还需看验证数据是否参与过训练、规则选择或调参；原文没交代时说明无法确认，不猜测一定发生了数据泄漏。

实用见解围绕不同的具体决策提出行动，解释依据、作用和边界，不把同一建议换句话重复列出。共通的抓取与证据限制集中说明，只有影响某一结论的特殊限制才单独补充。

索引从 `B0001` 起编号，给出块类型、完整抓取 Markdown 中的行号和短摘录，只帮助定位，不构成额外证据。输入保留一份原样抓取稿，不再重复拼接全文。对内部论证的评价不代表已验证外部事实。

抓取上下文包含扩展版本、抓取时间及安全的分阶段清理统计，并明确图片像素没有转写、外链与引用研究没有核验。清理比例表示解析阶段移除的文本量，不是正文缺失率，也不能单凭它认定论证不完整。原有内容提示阈值保持不变。

界面的“正文抓取正常”只表示正文选择和清理没有触发高影响提示，不表示图片或外部来源已经验证。普通复制和 Markdown 下载仍保持原始内容。扩展本身不调用模型 API，也不会上传页面内容。

日常使用只有一条流程：抓取 → 复制给模型 → 分析 → 在同一模型对话中提出意见 → 核对并修订。不满意时直接指出问题，例如“结论太泛”或“这条依据在哪里”。交接指令要求模型核对原文、区分事实错误与表达偏好、说明关键改动；用户意见缺乏依据时也应解释。一次纠正不会自动变成长期规则。

### 分析设置

在弹窗页头下方展开默认折叠的“分析设置”，可以填写分析偏好（默认留空）、反馈保存目录和 Obsidian 收藏目录，再点击“保存设置”。“恢复默认”会同时恢复三项默认值。配置仅保存在该扩展的 `localStorage` 中；普通复制与下载不包含这些设置。设置保存失败时会显示错误，各复制入口仍使用最近一次有效配置。

偏好默认仍为空，不会自动填入内置风格。留空时使用通俗中文、少术语、短段落；填写后只覆盖相应表达维度，例如“用英文”改变语言，“面向专业读者，保留术语”改变术语使用，未指定的维度继续采用默认值。偏好也可调整篇幅、重点和形式，但不能替代原文证据或取消事实边界。

在聊天中说“以后都这样”时，模型可整理出一条可复用偏好，由用户手动填回插件；扩展无法从聊天自动同步设置。

默认反馈目录为：

```text
/Users/chenghao/Documents/Code/content-catcher/.content-catcher/runs
```

可改为模型所在设备上的 POSIX 或 Windows 绝对路径；不支持空值、相对路径或控制字符。这个目录属于目标模型的文件系统，插件不会检查或创建它。

### 按需记录反馈

日常分析和普通修订都不要求写文件。只有在对话中明确说“把这次问题记下来”等保存请求时，具有文件能力的模型才按交接指令，向配置目录保存一份以 UTC 时间和短随机标识命名的 Markdown。记录仅包含来源、已知模型与提示版本、问题片段、用户意见、核对依据和修订结果；未知版本写 `unknown`，不保存完整文章、完整对话或隐含推理。

保存成功应返回实际路径；没有文件能力或写入失败时，应说明未保存并在聊天提供记录内容，不改换目录、不影响修订。扩展无法观察外部模型聊天、确认保存成功或保证模型遵守指令；保存状态须以模型实际操作结果为准。

项目默认的 `.content-catcher/runs/` 已加入 Git 忽略规则。记录只用于按需排查，不自动回填提示词、同步、评分或训练；公开问题时仍应先删减和脱敏。

### 按需收藏到 Obsidian

“复制收藏指令”是独立的 `archive-v2` 入口，打开弹窗即可使用，不需要先抓取当前页面。它只复制一段通用指令和已保存的收藏目录，不读取当前标签页、文章内容或模型对话。请在完成文章分析和必要修订后，把指令粘贴到包含该文章抓取稿与最终分析的同一对话中；按钮显示“已复制”只表示剪贴板写入成功，不表示笔记已经保存，剪贴板失败会明确提示。

默认收藏目录为：

```text
/Users/chenghao/Documents/Obsidian Vault/文章收藏
```

目录可在分析设置中改为模型所在设备上的 POSIX 或 Windows 绝对路径。旧版设置缺少该项时使用默认目录，不改写原有偏好和反馈目录。未保存的输入、非法路径或本地存储失败不会替换最近一次有效设置。

收藏指令要求有文件能力的模型只使用当前对话已经提供并最终确认的材料，保存一份 Markdown 阅读笔记和原样抓取稿，不保存完整对话或隐含推理。对话中存在多篇文章、缺少抓取原文或最终分析时应先询问，不能猜测或联网补全；来源、作者等未知字段标记为 `unknown`。远程图片链接不代表图片已备份，模型不应下载图片，也不能声称外部研究已经核验。

收藏原文统一在独立章节直接呈现 Markdown，不额外把整篇放进代码块；原文自己的代码块、元数据和空白保持原样。聊天中为复制提供的外层代码围栏不写入实际文件，保存后应核对。已有笔记不会自动批量修改。

保存前只在配置目录内检查相同来源和同名文件。发现重复或不能确认冲突时先询问，不覆盖、合并或修改已有笔记。保存成功后应返回实际路径；没有文件能力或写入失败时明确说明未保存，并提供可手动保存的 Markdown，不更换目录。扩展本身不会创建 Obsidian 目录、观察或验证外部模型的写入，也不会执行 Git 提交或推送。

## 诊断样本

解析完成后点击“导出脱敏诊断样本”，扩展会保留 DOM 层级、常见选择器、等长安全文本和语义噪声标记，同时替换原始正文、替代文本以及图片和链接地址。诊断 schema v3 的摘要还会记录正文选择方式、候选评分、元数据来源及清理前后统计，并按结构、占位图、噪声和站点尾部四个阶段记录计数；不保存被删除的原文，也不记录元数据原值。诊断样本只下载到本地，是否提交到 issue 由用户决定。
